# 多语言发布规范

本文档定义网站的语言版本、翻译状态、页底提示和发布检查规则。新增语言或页面时必须遵守这些规则。

## 语言与翻译状态

- 简体中文（`zh-Hans`）是当前文章的原始语言，使用 `translation_status: original`。
- 英文（`en`）由作者审校，使用 `translation_status: author-reviewed`。
- A1 语言均视为 AI 翻译，使用 `translation_status: ai-translated`。
- AI 翻译必须保留 `source_locale` 和 `source_hash`，不得暗示已经过作者审校。

A0 权威参考语言、A1 第一批 AI 翻译候选语言及其出处和推导规则，见 [翻译语言发布等级：A0 与 A1](translation-language-tiers.md)。

## 翻译与写作风格

所有译文首先忠实于原文的事实、论证、限定条件和作者立场，然后才追求目标语言的流畅。英文及其他语言应借鉴 Paul Graham 长篇文章中适合长期留存的高层写作原则，但不得模仿其标志性措辞或个人语言习惯：

1. 从作者自己的观察、实践或问题出发，让引用承担证据和历史坐标的作用，不让名人或流行术语替代作者的声音。
2. 使用目标语言中自然、直接、克制的书面表达；优先使用具体名词和动词，避免宣传腔、学术腔、空泛修饰和为了显得深刻而增加的修辞。
3. 保持短段落和清晰推进。每个段落完成一个主要动作：提出事实、说明边界、作出推论或提出问题。
4. 为长期可读性写作。保留必要的时间和技术背景，但不把文章组织成对短期热点的回应，也不擅自增加预测。
5. 严格保留不确定性和事实边界。例如“尚未发布”“尚未经过市场验证”“不适用于所有软件”等限定不得弱化、删除或改写成成功声明。
6. 不逐字复制中文语序。标题、段落节奏、术语说明和标点应符合目标语言的编辑习惯，但不得改变论证顺序和因果关系。
7. 保留 Markdown 结构、链接、引用编号、专有名词、日期和 `entity-*` 标识。不得虚构例子、事实、来源或作者没有表达的判断。
8. AI 译文完成后仍需检查标题、摘要、开头、结尾和参考资料；流畅不等于已经过作者审校，翻译状态必须如实填写。

这里所说的“对齐”是对齐简洁、清晰、由具体观察通向一般结论的编辑原则，而不是复制任何在世作者的独特风格。目标是让文章脱离发布当时的热点语境后，仍能独立成立。

## 页底提示

所有 A1 页面都必须在页面底部显示 AI 翻译提示。主页和文章页采用同一规则：

1. 用当前页面的语言说明该版本由 AI 翻译。
2. 提供当前页面对应的英文版和中文版链接。
3. 链接必须是带显式语言前缀的站点根相对路径，例如 `/en/`、`/zh-Hans/`、`/en/essay/<slug>/`，不得写死域名。
4. A0 页面不显示此提示；包括繁体中文在内的 A1 页面仍须显示。
5. A1 文章缺少英文或简体中文对应版本时，构建必须失败，不得发布不完整的语言版本。

参考语言判定集中在 `lib/i18n/policy.ts`，提示由 `components/TranslationNotice.tsx` 统一生成，界面文案集中维护在 `lib/i18n/messages.ts`。新增语言时必须补齐目标语言文案；英文兜底仅用于开发阶段，不应作为正式发布文案。

日语示例：

> 日本語版はAI翻訳です。英語版または中国語版をご覧ください。

其中“英語版”和“中国語版”分别链接到同一页面的英文版与中文版。

## 路由与自动匹配

- 所有正式页面都使用显式语言前缀。英文为 `/en/`，简体中文为 `/zh-Hans/`，日语为 `/ja/`；文章路径同样带前缀，如 `/en/essay/<slug>/`。
- `/` 仅作为自动语言入口：优先读取用户手动保存的语言，其次匹配 `navigator.languages`，没有匹配项时跳转 `/en/`。
- 访问任何显式语言路径后不得再执行自动跳转。用户打开 `/en/...` 时必须始终停留在英文版。
- 历史无前缀文章路径 `/essay/<slug>/` 仅作为兼容入口，按相同规则跳转到显式语言版本；该入口使用 `noindex`，不进入 Sitemap。
- 手动选择语言的优先级高于系统语言，并保存在浏览器本地。用户之后访问 `/` 时优先使用该选择。

## 语言选择器

页面顶部必须提供语言选择入口，以便用户覆盖自动识别结果。视觉与交互规则如下：

1. 顶部只显示无文字的线性地球 SVG 图标，不使用 emoji、国旗、胶囊或当前语言文字。
2. 图标视觉尺寸为 18–20 px，实际点击区域不得小于 44 × 44 px；必须提供本地化 `aria-label`、键盘焦点状态和 tooltip。
3. 桌面端打开居中对话框，移动端打开接近全屏的底部面板。两者都必须支持键盘关闭、点击遮罩关闭和独立滚动。
4. 搜索同时匹配语言自称、当前界面的语言名称、英文名称和语言标签，例如 `日本語`、`日语`、`Japanese`、`ja`。
5. 语言名称以自称为主，例如 `English`、`简体中文`、`日本語`、`العربية`；不得使用国旗代表语言。
6. 当前语言使用对勾和轻微底色标识。当前页面没有对应译文时，必须明确显示不可用状态，不得悄悄跳到该语言首页。
7. 选择器只列出已经发布的语言。语言数量较多时显示当前语言、浏览器偏好和最近使用语言组成的推荐区。
8. 选择器中的可用项使用真实 `<a href>`，并使用带语言前缀的相对路径。

## SEO、GEO 与机器可读资源

每个新语言版本都必须进入以下输出：

- canonical 与 `hreflang`
- Open Graph 与 Twitter 元数据
- JSON-LD 中的 `inLanguage`、`translationOfWork` 和 `workTranslation`
- `/sitemap.xml`
- `/feed.xml`
- `/llms.txt` 与 `/llms-full.txt`

SEO 路由约定：

- 每个显式语言页面使用自身 URL 作为 canonical。
- 主页的 `hreflang="x-default"` 指向自动入口 `/`。
- 文章的 `x-default` 指向显式英文版，避免为每篇文章建立可索引的无前缀副本。
- Sitemap 只收录显式语言页面，不收录自动入口或兼容跳转入口；不同语言版本通过 `hreflang` 相互关联。

这些资源由内容目录和元数据函数自动生成，但发布前仍需通过测试确认。

## 机构实体与外部链接

人物经历中出现的公司、高校及其他重要机构应通过链接指向其第一方官方网站，以增强事实的可验证性，并帮助搜索引擎和 AI 建立清晰的实体关系。内容编辑必须遵守以下规则：

1. 每个机构仅在正文第一次出现时添加链接；后续出现保持纯文本，避免干扰阅读。
2. 仅链接机构的官方站点，不使用百科、搜索结果页、社交媒体或第三方介绍页代替官网。
3. 简体中文内容使用中文官网；英文及其他语言默认使用英文官网。机构有适合目标语言的官方版本时，可在集中配置中补充精确映射。
4. 外链使用普通链接，不强制新窗口打开，也不添加与事实关系无关的追踪参数。
5. 机构网址统一维护在 `site.config.ts` 的 `entities` 中。Markdown 使用 `[机构名称][entity-配置键]`，不得在各语言正文中重复写死网址。
6. 新增或修改机构链接时，必须确认目标页面可公开访问，并检查静态 HTML 与结构化数据中的最终 URL。

示例：

```markdown
[深度飞轮][entity-deepflywheel]
[商汤科技][entity-sensetime]
[南京大学][entity-nanjingUniversity]
[清华大学][entity-tsinghuaUniversity]
```

`entity-deepflywheel` 使用 `site.config.ts` 的 `company.url`；其他机构使用 `entities` 配置。`renderMarkdown` 会根据当前内容语言注入对应的官方链接定义。翻译时必须保留 `entity-*` 引用标识，只翻译需要本地化的可见机构名称。

## 新增语言检查清单

1. 确认语言标签、发布等级、内容角色和翻译状态已列入 `config/locales.json`。
2. 在 `content/pages/home/<locale>.md` 添加首页介绍、SEO 标题、描述、翻译状态和来源哈希。
3. 在 `content/essays/<slug>/<locale>.md` 添加文章译文，并填写正确的翻译状态和来源哈希。
4. 在 `lib/i18n/messages.ts` 补齐日期、目录、阅读时长、主题按钮、语言选择器和翻译提示等界面文案；`site.config.ts` 仅维护跨语言共用的事实与链接。
5. 在 `TranslationNotice` 中添加目标语言的页底提示。
6. 确认每篇 A1 内容都有对应的英文版和简体中文版。
7. 确认语言选择器能按同一页面切换、搜索该语言，并能标识缺失译文。
8. 运行 `npm test`、`npm run lint`、`npm run typecheck`，并在桌面端和移动端检查主页、文章页与语言面板。
