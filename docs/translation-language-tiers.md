# 翻译语言发布等级：A0 与 A1

本文独立定义 liweiwu.com 的 A0、A1 翻译语言发布等级，以及 A1 的来源、推导方法和适用边界。

这是一套项目内部的发布与验证优先级，不是 OpenAI 对 Codex 文本翻译质量的官方评级，也不表示同一等级内的所有语言具有完全相同的翻译质量。

## 适用范围

本规范用于决定：

- 哪些语言是内容的权威参考版本；
- 哪些语言可以进入第一批 AI 翻译、验证和发布流程；
- 翻译状态应如何标记；
- 项目在引用外部产品能力时应如何陈述证据和限制。

`config/locales.json` 是 A0/A1 的机器可读配置。ISO 语言代码全集不再作为翻译目标清单；未列入 A0 或 A1 的语言不能自动获得批量翻译或发布资格。

## 等级定义

### A0：权威参考语言

A0 是内容含义、事实、论证和限定条件的权威参考版本。

| 语言代码 | 语言 | 内容角色 | `translation_status` |
| --- | --- | --- | --- |
| `zh-Hans` | 简体中文 | 作者原文和首要事实依据 | `original` |
| `en` | 英语 | 作者审校的跨语言参考版本 | `author-reviewed` |

A0 语言不得由批量翻译脚本覆盖。中文原文与英文审校版存在表达差异时，应先由作者解决差异，再将修订传播到其他语言。

### A1：第一批 AI 翻译候选语言

A1 是优先进入 AI 翻译、自动检查、人工抽检和发布流程的目标语言集合。

| 语言代码 | 语言 | 推导依据 |
| --- | --- | --- |
| `zh-Hant` | 繁体中文 | OpenAI 官方列表中的 `Chinese`；项目将其映射为尚未由 A0 覆盖的中文文字版本 |
| `es` | 西班牙语 | OpenAI 官方目标输出语言 `Spanish` |
| `pt` | 葡萄牙语 | OpenAI 官方目标输出语言 `Portuguese` |
| `fr` | 法语 | OpenAI 官方目标输出语言 `French` |
| `ja` | 日语 | OpenAI 官方目标输出语言 `Japanese` |
| `ru` | 俄语 | OpenAI 官方目标输出语言 `Russian` |
| `de` | 德语 | OpenAI 官方目标输出语言 `German` |
| `ko` | 韩语 | OpenAI 官方目标输出语言 `Korean` |
| `hi` | 印地语 | OpenAI 官方目标输出语言 `Hindi` |
| `id` | 印度尼西亚语 | OpenAI 官方目标输出语言 `Indonesian` |
| `vi` | 越南语 | OpenAI 官方目标输出语言 `Vietnamese` |
| `it` | 意大利语 | OpenAI 官方目标输出语言 `Italian` |

A1 表示“优先验证和发布的候选语言”，不表示：

- 已经经过作者或母语者审校；
- 达到专业人工翻译质量；
- 适用于无需复核的法律、医疗、财务或安全关键内容；
- OpenAI 已经为 Codex 文本翻译单独认证该语言；
- 语言变体、地区习惯和文字系统已经被完整覆盖。

## A1 的出处

### 主要依据

A1 的主要依据是 OpenAI 官方 Cookbook 的 [Build Live Translation Apps with gpt-realtime-translate](https://developers.openai.com/cookbook/examples/voice_solutions/realtime_translation_guide#supported-languages)。截至 2026 年 8 月 4 日，该页面原文为：

> “Realtime Translation currently supports 13 target output languages: Spanish, Portuguese, French, Japanese, Russian, Chinese, German, Korean, Hindi, Indonesian, Vietnamese, Italian, and English.”

原文列出 13 种目标输出语言：西班牙语、葡萄牙语、法语、日语、俄语、中文、德语、韩语、印地语、印度尼西亚语、越南语、意大利语和英语。

该来源描述的是 OpenAI 的专用实时语音翻译模型，不是 Codex 文本翻译模型。因此，本项目只把它视为 OpenAI 对目标输出语言进行保守产品化选择的公开证据，用来确定第一批验证范围，不把它表述为 Codex 的翻译质量保证。

### 项目内推导过程

官方 13 种目标语言按以下规则映射为本项目的 A0 和 A1：

1. `English` 映射为 `en`，但英文已经属于 A0 作者审校版，因此不再进入 A1。
2. `Chinese` 是官方原文使用的宽泛名称。项目中的 `zh-Hans` 已属于 A0 原文，因此把尚未覆盖的 `zh-Hant` 放入 A1。
3. 其余 11 种官方目标语言按项目当前使用的语言标签直接进入 A1。

由此得到 2 个 A0 语言和 12 个 A1 目标语言。

### 关于繁体中文的限制

OpenAI 的出处只写 `Chinese`，没有分别声明简体中文与繁体中文，也没有区分台湾、香港或其他地区变体。将 `Chinese` 映射为 `zh-Hant` 是项目自身的发布决策，而不是官方对繁体中文的单独认证。

发布繁体中文时，应至少检查：

- 是否真正使用繁体字形，而不是仅进行机械字形转换；
- 术语和句法是否符合目标读者的自然书面表达；
- 是否需要进一步区分 `zh-Hant-TW` 与 `zh-Hant-HK`；
- 专有名词、引文、技术术语和标点是否符合选定地区的惯例。

## 辅助证据

OpenAI 的 [多语言 API 说明](https://help.openai.com/en/articles/6742369-how-do-i-use-the-openai-api-with-text-in-different-languages) 表明，其模型接受并生成多种语言，但模型仍以英语为主要优化语言。该说明支持“模型具有多语言能力”，但没有提供逐语言文本翻译认证。

[GPT-5.2 System Card](https://cdn.openai.com/pdf/3a4153c8-c748-4b71-8e31-aecbde944f8d/oai_5_2_system-card.pdf) 公布了阿拉伯语、孟加拉语、中文、法语、德语、印地语、印度尼西亚语、意大利语、日语、韩语、葡萄牙语、西班牙语、斯瓦希里语和约鲁巴语的多语言 MMLU 结果。这些结果衡量多语言理解和推理，不是机器翻译质量，因此只能作为辅助证据，不能直接决定 A1。

## A1 的发布要求

A1 译文仍然属于 `ai-translated`。发布前必须满足现有《多语言发布规范》，并至少完成以下检查：

1. 保留标题、摘要、正文、Markdown 结构、链接、引用编号、实体标识、日期和数字。
2. 不得增加、删除或弱化事实、因果关系、不确定性和适用边界。
3. 检查目标语言是否正确，是否残留非预期的中文或英语段落。
4. 检查专有名词、技术术语、数字、日期和引用。
5. 对标题、摘要、开头、结尾和高风险段落进行人工抽检。
6. 页面明确标记为 AI 翻译，并提供同页英文版和中文版链接。

A1 语言首次发布或翻译模型发生变化时，应从实际文章中建立代表性测试集。测试结果可以将某个语言暂缓发布或降出 A1；外部名单不能覆盖项目自身观察到的质量问题。

## 维护规则

出现以下情况时，应复核本规范：

- OpenAI 更改专用翻译产品的目标输出语言列表；
- 项目更换主要翻译模型或翻译流程；
- A1 语言在项目测试中出现系统性质量问题；
- 项目开始正式区分地区、文字或方言变体；
- 新增作者审校或母语者审校的权威版本。

更新 A1 时必须同时记录来源、访问日期、项目映射规则和适用边界。仅有“模型可以输出这种语言”不足以成为加入 A1 的依据。

语言等级发生变化时，必须同步更新 `config/locales.json`、本规范和相关测试，确保机器执行范围与发布政策一致。
